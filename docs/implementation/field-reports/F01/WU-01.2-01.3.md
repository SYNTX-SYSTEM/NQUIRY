# WORK UNIT REPORT
FIELD: F01 — IDENTITY · WORKSPACE · GOVERNANCE
WORK_UNIT: WU-01.2 (accessible Workspace query) + WU-01.3 (current
Workspace semantic context), merged per 19 §21's own explicit
permission ("Claude Code may merge/reorganize Work Units") — both are
small, closely related read-side extensions building directly on
WU-01.4b's real `CreateWorkspace` Command.

## Mission
WU-01.2: close 19 §21's own disclosed CURRENT FIELD gap ("Workspace
discovery -> incomplete") — let a real, verified human see which
Workspaces they can access. WU-01.3: complete 11 §7's full
"AUTHENTICATED USER + REQUESTED WORKSPACE + CURRENT WorkspaceMembership
+ TARGET OBJECT WORKSPACE -> CONSISTENT WORKSPACE CONTEXT" formula —
`application.workspace_context` (PKG-01) had explicitly left the
membership half unchecked, disclosed in its own docstring as "until a
later package adds the membership check."

## Files changed

### Created
- `packages/application/accessible_workspaces_query.py` —
  `list_accessible_workspaces()`, `AccessibleWorkspacesDenied`. BND-001
  only (no single target Workspace exists to check BND-002/003
  against — same reasoning `workspace_creation_handler` already used).

### Modified
- `packages/persistence/membership_repository.py` — added
  `list_active_memberships_for_user()` (Protocol + implementation),
  the previously-absent "given only a user, find their Workspaces"
  read.
- `packages/application/workspace_context.py` — `WorkspaceContext`
  gained a required `membership: MembershipRecord` field;
  `resolve_workspace_context()` gained a required
  `membership_repository` parameter and now raises the new
  `NotAWorkspaceMemberError` for a real Workspace the principal is not
  an ACTIVE member of (previously unchecked — the PKG-01-era disclosed
  gap this Work Unit closes).
- `tests/domain/test_workspace_context.py` — the 4 existing tests
  updated to the new, completed contract (their previous 3/2-argument
  calls would no longer type-check); 2 new tests added
  (`test_resolve_workspace_context_fails_closed_for_a_non_member`,
  `..._for_a_revoked_member`) covering the mandatory adversarial
  attack "cross-Workspace isolation" (19 §21 TESTS FIRST) this
  extension makes newly checkable.

No other caller of `resolve_workspace_context`/`WorkspaceContext`
existed anywhere in the codebase (confirmed by grep before editing) —
this extension breaks nothing beyond its own owning tests, which were
updated in the same change.

## Relation materialized
WU-01.2: "verified human -> the set of Workspaces they currently hold
ACTIVE membership in" (19 §21 HUMAN PRODUCT EFFECT: "authenticate ->
see accessible Workspaces"). WU-01.3: "verified human + one requested
Workspace -> proven Workspace existence AND proven current membership,
paired" — the actual, complete `WorkspaceContext` 11 §7 always meant.

Both Work Units' tests were written immediately after each function's
design, before any live-database run — both ran GREEN on the first

WU-01.4b's prior run having already surfaced and fixed every
`CommandEnvelope`/repository-layering pitfall these two, simpler,

## Implementation
No new architecture invented. WU-01.2 mirrors
`session_view_query.GetSession`'s own established minimal read-chain
precedent (Architecture 17), scoped down to BND-001 only because there
is no single target Workspace for this particular query. WU-01.3
mirrors `SqlAlchemyWorkspaceRepository`/`SqlAlchemyMembershipRepository`'s
existing `get`/`get_current_membership` reads directly — no new
repository method was needed, only wiring the two together in the
already-forward-referenced way.

## Negative / adversarial tests
- Non-human actor denied `list_accessible_workspaces` (BND-001),
  repository never queried (proven with a fake repository that raises
  if called at all) — parametrized over `SYSTEM_SERVICE`/`AI_PROCESSOR`/
  `EXTERNAL_SYSTEM`.
- Cross-user isolation: founder B never sees founder A's Workspace.
- Revoked membership excluded from both the accessible-list query and
  `resolve_workspace_context` (two separate tests, one per Work Unit).
- Human with zero memberships gets an empty list, not a denial —
  distinguishing "legitimately nothing yet" from "forbidden."
- `resolve_workspace_context` for a real Workspace with an outsider
  principal: `NotAWorkspaceMemberError`, not a false ALLOW.
- Forged-context type checks re-verified for the now-3-field
  `WorkspaceContext`.

## Known limitations
- `list_accessible_workspaces` returns raw `WorkspaceRecord`s only; it
  does not yet indicate the caller's role or authority within each
  Workspace (that is WU-01.7's own "capability semantic projection"
  scope, not invented here).
- `resolve_workspace_context` still does not check
  `HumanAuthorityBinding`/role — it proves membership only, not
  authority, by design (11 §7's own formula stops at membership; BND-004
  role-context and BND-005 human-authority remain separate, later
  checks a Command-side handler performs, same non-collapse boundary
  `session_view_query.py`'s own docstring already established).
