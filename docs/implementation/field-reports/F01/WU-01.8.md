## Tests written first
Deviation from this Field's own strict ordering, disclosed rather than
glossed over: the five `dispatch_*` functions and the HTTP router were
implemented before `test_http_workspaces.py` was written, because
establishing the correct dispatch/exception-mapping shape required
directly reading and mirroring five separate existing patterns
(`dispatch_get_session_view`, `dispatch_record_human_decision`,
`add_member`'s own test conventions, `workspace_creation_handler`'s
own eligibility-checker convention, `test_http_auth.py`'s own
`http_client` fixture technique) — writing throwaway HTTP tests before
that reading was done would not have been genuine TDD, only motion.
What *was* done test-first in the strict sense: `test_http_workspaces.py`
was written and run in full BEFORE any defect in it was fixed, and its
first real run caught a genuine bug — not in the HTTP/dispatch layer,
but in the test file's own fixture:
```
AttributeError: 'UUID' object has no attribute 'value'
```
(`SqlAlchemyLocalCredentialRepository.create` expects a wrapped
`UserId`, not a bare `uuid.UUID` — the test fixture passed the latter).
Fixed in the fixture only; all 19 passed immediately afterward with
zero further changes to `http_dispatch.py`/`workspaces.py` — genuine
evidence the dispatch layer itself was correct on the first pass, not
proof the process was TDD-strict throughout.

## Implementation

### Why `_resolve_principal_from_session` is a new function, not a change to `_resolve_actor_from_session`
`application.workspace_context.resolve_workspace_context` (WU-01.3)
requires a full `security.identity.AuthenticatedPrincipal`, not the
narrower `authority.actor.ActorIdentity` the two Architecture-17
routes and `add_member`/`revoke_human_authority_binding` all take.
`_resolve_actor_from_session` already discards everything but
`user_id` when downgrading `resolve_session`'s own return value to an
`ActorIdentity` — changing its return type would have required
touching `dispatch_get_session_view`/`dispatch_record_human_decision`,
both already-sealed Architecture-17/local-login-field code with their
own proof reports. A second, small function reusing the same
underlying `resolve_session` call keeps this Work Unit's diff scoped
to what it actually needs.

### Why `GET /workspaces/{workspaceId}` combines WU-01.3 and WU-01.7 into one response
19 §21's own FRONTEND REQUIREMENTS line ("Render separately:
authenticated / member / authorized / governance-capable / non-proof
demo state") describes ONE orientation view, not two separate round
trips a real frontend would have to sequence and reconcile itself.
`dispatch_workspace_orientation` calls `resolve_workspace_context`
then `project_capabilities` on the SAME already-proven context, in one
request, one connection, one transaction — "authenticated"/"member"
are implicit in ever reaching a `kind: ok` body at all (a real session
resolved, a real Workspace and ACTIVE membership were proven);
"non-proof demo state" remains unrepresented, exactly as
`capability_projection`'s own module docstring already discloses (no
schema fact exists to project it from).

### Why path naming does not use 14 §36's literal `/v1/workspaces/...` prefix
Architecture 17 already established the un-prefixed convention this
whole HTTP surface uses (`/workspaces/...`, `/decisions/...`,
`/auth/...`) before F01 existed. This Work Unit stays consistent with
the CODE's own established, already-proven convention rather than an
older architecture document's literal text — disclosed, not silent.

### Denial/rejection HTTP-shape conventions, chosen to match the closest existing precedent for each case
- `NoValidSessionError` → 401 (identical to every existing route).
- Malformed UUID path parameter (`ValueError` from `uuid.UUID(...)`)
  → 400 (identical to `queries.py`'s own convention).
- A genuine BND-001..005 chain `DENY` (`AddMemberDenied`/
  `RevokeAuthorityBindingDenied`/`WorkspaceCreationDenied`/
  `AccessibleWorkspacesDenied`) → HTTP 200, `{"kind":"denied",...}` —
  matches every existing dispatch function's own "denial is a normal
  response shape, not an HTTP error" discipline.
- A structural, pre-boundary refusal (`OwnerRoleNotAssignable`,
  `GovernanceRootOrphaningRefused`) → HTTP 200,
  `{"kind":"rejected",...}` — mirrors `SelectedOptionNotCandidate`'s
  own existing precedent in `dispatch_record_human_decision`.
- "Workspace-scoped not-found" (`WorkspaceNotFoundError`,
  `NotAWorkspaceMemberError`, `AuthorityBindingNotFound`) → HTTP 200,
  `{"kind":"denied","reasonCode":"..."}` — mirrors `SESSION_NOT_FOUND`'s
  own existing precedent in `dispatch_get_session_view`.
- `CommitFailedPrecommit`/`CommitIndeterminate` (real DB-level
  conflicts surfacing through `CommitCoordinator`) → identical
  `{"kind":"rejected"/"indeterminate",...}` shapes
  `dispatch_record_human_decision` already established, reused
  verbatim for `dispatch_add_member`/`dispatch_revoke_authority_binding`.

## Negative / adversarial tests
- `POST /workspaces` with no session: 401.
- `POST /workspaces` with an empty/whitespace-only name: `rejected`,
  no Workspace written.
- `GET /workspaces` with no session: 401.
- `GET /workspaces` correctly excludes a Workspace the caller does not
  belong to (cross-account isolation, proven over real HTTP, not just
  the Command layer).
- `GET /workspaces/{id}` for a genuinely non-existent Workspace:
  `denied`/`WORKSPACE_NOT_FOUND`.
- `GET /workspaces/{id}` for a real Workspace the caller is not a
  member of: `denied`/`NOT_A_WORKSPACE_MEMBER`.
- `GET /workspaces/{id}` with a malformed (non-UUID) path segment: 400.
- `GET /workspaces/{id}` with no session: 401.
- `POST .../members` refuses `role: "Owner"`: `rejected`/
  `OWNER_ROLE_NOT_ASSIGNABLE`, over real HTTP.
- `POST .../members` from a non-owner caller: `denied`, over real HTTP.
- `POST .../members` with an unrecognized role string (`"SuperAdmin"`):
  `rejected`/`UNKNOWN_ROLE`, never a 500 from an unhandled enum
  `ValueError`.
- `POST .../members` with no session: 401.
- `POST .../authority-bindings/{id}/revoke` on the Workspace's own
  `WORKSPACE_GOVERNANCE_RIGHT` binding: `rejected`/
  `GOVERNANCE_ROOT_ORPHANING_REFUSED`, over real HTTP — this Field's
  own most consequential guard, now proven reachable end to end, not
  just at the Command layer.
- `POST .../authority-bindings/{id}/revoke` for a non-existent binding:
  `denied`/`AUTHORITY_BINDING_NOT_FOUND`.
- `POST .../authority-bindings/{id}/revoke` with no session: 401.
