## Implementation

### Real defect #1 (this Work Unit's own): a stale, un-rebuilt `web` container silently served an old frontend
The first full `workspaces.spec.ts` run failed all 10 tests, including
the simplest one (unauthenticated redirect). Root cause: WU-01.8's own
`docker compose ... up -d --build api` rebuilt only the `api`
container for its own live-HTTP smoke test — the `web` container was
never rebuilt, so `localhost:3000` (which Playwright's own
`reuseExistingServer: true` config happily reuses) was still serving
the PRE-WU-01.9 frontend image, with no `/workspaces` route baked in
at all. Fixed by rebuilding `web` (`docker compose -p nquiry --profile
app up -d --build web`); all 10 tests then passed on the very next
run with zero code changes. Disclosed because it is exactly the class
of "container up != application reflects current code" trap
`docs/RUNTIME_OPERATION.md` already warns about for the `api`/`web`
services' own lack of a live volume mount — this is the first time in
this Field it was actually hit, not merely a known limitation restated.

### Real defect #2 (this Work Unit's own test file): HTML5 `required` validation blocked a rejected-creation test
`test("a rejected creation ...")` originally tried to submit an empty
`<input required>` via `page.evaluate()` DOM manipulation to strip the
attribute first — unreliable, and the real failure showed the browser
still blocking submission. Fixed by filling the field with `"   "`
(whitespace-only) instead: passes the browser's own HTML5 `required`
check (non-empty from its point of view) while still exercising the
real server-side `WORKSPACE_NAME_REQUIRED` rejection this test exists
to prove. A test-file-only fix; no product code changed.

### Why `LogoutButton` moved from `app/page.tsx` onto `app/workspaces/page.tsx`
`app/page.tsx` no longer has a state that stays rendered long enough
for a person to click anything — it is now purely a redirect-decision
screen (`/login`, a configured default Session, or `/workspaces`).
`/workspaces` is the new de-facto landing screen for anyone without a
configured default Session, so it is the page that now needs a real
way back to `/login`, mirroring exactly why the Session-view page
already carries its own copy (that page's own docstring).

### Why the orientation page is a plain Client Component (`useParams()`), not the Server-shell-plus-Container split the Session-view route uses
Disclosed, not a claim the other pattern is wrong: both achieve the
one real requirement (`lib/api/client.ts`'s own docstring — the fetch
must run in the browser for Playwright's `page.route()` interception
to see it). This Work Unit's own two new pages use the simpler,
single-Client-Component shape consistently with each other.

**Real type error found and fixed**: `GovernanceActionResult`'s
`"indeterminate"` case carries `blockedTargetRef`, not `reasonCode` --
the Add-Member error handler in
`app/workspaces/[workspaceId]/page.tsx` originally read
`result.reasonCode` unconditionally, which `tsc` correctly rejected
(`result.reasonCode` does not exist on the `indeterminate` member of
the union). Fixed by branching on `result.kind` before reading either
field. A real compile-time catch of a real runtime bug (would have
been `undefined` in the UI for an indeterminate outcome), not a
stylistic nit.

  choked on was traced directly: workspace_id
  `7b09d80b-151a-4363-af67-1a0d8044c1da` — **"Live WU-01.8 Proof
  Workspace"**, the real, genuinely-committed Workspace WU-01.8's own

  (non-fixture, non-test-transaction-rolled-back) `commit_units` row
  ever written to this shared database in this Field's own history —
  no earlier Work Unit's own live proof ever committed a real
  `CreateWorkspace` durably before.
- `test_outbox_worker.py`'s own `KeyError: UUID('d5c60297-...')` traces
  to `OutboxWorker.deliver_due()` correctly, by design, processing
  EVERY currently-PENDING `outbox_events` row (production-correct
  behavior — a real worker must not ignore real pending work) — it
  picked up the real, still-undelivered `WORKSPACE_CREATED` event that
  same live `curl` call produced (the worker has no continuous loop
  wired, per its own long-disclosed `BLOCKED_BY_UPSTREAM_GAP`), and the

- `test_habb_grant_constraints.py` — the already-known case, count now
